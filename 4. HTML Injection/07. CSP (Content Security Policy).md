
#  Content Security Policy (CSP)

##  What is CSP?
Content-Security-Policy (CSP) is a modern browser security mechanism designed to mitigate attacks like XSS (Cross-Site Scripting) and data injection by strictly controlling which resources (scripts, images, styles, etc.) a page can load.


* **Content Security Policy (CSP)** is a security HTTP response header that defines **which resources (scripts, images, styles, etc.)** are allowed to load in a web application.
* It helps protect against **Cross-Site Scripting (XSS)**, malicious payloads, and code injections.
* In short, CSP acts as a **whitelist for browser resources**, ensuring that only trusted content executes.

---

## Role of CSP in XSS Protection

* If an attacker injects malicious scripts in the browser, a properly configured CSP **prevents their execution**.
* Thus, CSP significantly reduces the attack surface of **XSS vulnerabilities**.

---

## How CSP Works

* The **server** sends CSP rules via:

  * **HTTP headers** (preferred)
  * or `<meta http-equiv="Content-Security-Policy">` tags.
* The **browser enforces** these rules and only executes resources from the allowed sources.

---

## Important CSP Directives

* `default-src` → Default source for all resources.
* `script-src` → Allowed sources for JavaScript.
* `img-src` → Allowed sources for images.
* `style-src` → Allowed sources for CSS.
* `media-src` → Allowed sources for audio/video.

---

## ✅ Example of a Safe CSP

```http
Content-Security-Policy: default-src 'self'; script-src 'self';
```

* `'self'` → Only resources from the same origin are allowed.
* Any **inline scripts** or **external untrusted scripts** will be blocked.

---

## ⚠️ Weak / Misconfigured CSP Examples

1. **Wildcard (`*`) usage**

```http
Content-Security-Policy: script-src *;
```
Allows scripts from **any domain** (very dangerous).

2. **Allowing `unsafe-inline`**

```http
Content-Security-Policy: script-src 'self' 'unsafe-inline';
```
Inline JavaScript like `<script>alert(1)</script>` will execute.

3. **Allowing `unsafe-eval`**

```http
Content-Security-Policy: script-src 'self' 'unsafe-eval';
```
Dangerous functions such as `eval()`, `new Function()`, and `setTimeout("code")` can execute.

4. **Trusted but Compromised Domain**

```http
Content-Security-Policy: script-src 'self' https://cdn.example.com;
```
If `cdn.example.com` is hacked, attackers can inject malicious scripts that will load without restrictions.

---

##  Common CSP Bypass Techniques

1. **Unsafe Directives**

   * Usage of `'unsafe-inline'` or `'unsafe-eval'`.
   * Allows inline scripts, event handlers, or eval-based code execution.

2. **Compromised Trusted Domains**

   * Malicious scripts can load from whitelisted but compromised domains (e.g., CDNs).

3. **Wildcards & Insecure Schemes**

   * Allowing `*`, `data:`, `blob:`, or `filesystem:` sources lets attackers inject uncontrolled scripts.

4. **DOM-Based CSP Bypass**

   * Exploiting client-side flaws (e.g., `innerHTML`, `document.write`, `location.hash`) bypasses CSP protections.

5. **Browser Vulnerabilities**

   * Exploiting quirks or bugs in CSP implementation in certain browsers.

6. **JSONP & Script Gadgets**

   * Using JSONP endpoints or script gadgets in trusted libraries (like jQuery/Angular) to execute attacker-controlled code.

---

## How to Prevent CSP Bypass

*  Avoid `'unsafe-inline'` and `'unsafe-eval'`.
*  Restrict trusted sources to only required domains.
*  Avoid wildcards (`*`, `data:`, `blob:`) unless absolutely necessary.
*  Use **nonce-based** or **hash-based** CSP to control inline scripts securely.
*  Regularly test policies with tools like [Google CSP Evaluator](https://csp-evaluator.withgoogle.com/).

```bash
Content-Security-Policy: img-src 'self' /assets/public/images/uploads/default.svg; script-src: 'self' 'unsafe-eval' https://code.getmdl.io http://ajax.googleapis.com
```
### img-src 'self' /assets/public/images/uploads/default.svg
* This directive controls the sources from which images can be loaded.
* 'self' means images can be loaded only from the same origin as the webpage (same domain).
* /assets/public/images/uploads/default.svg allows images specifically from this exact relative path on the same server.
* So, images can come from your own domain and the specific image path /assets/public/images/uploads/default.svg.

### script-src: 'self' 'unsafe-eval' [https://code.getmdl.io](https://code.getmdl.io), [http://ajax.googleapis.com](http://ajax.googleapis.com)

* This directive controls the sources from which JavaScript can be loaded and executed.
* 'self' allows scripts to be loaded from the same domain.
* 'unsafe-eval' allows the use of JavaScript constructs such as eval() or new Function(), which are generally risky as they can execute arbitrary code.
* [https://code.getmdl.io](https://code.getmdl.io) and [http://ajax.googleapis.com](http://ajax.googleapis.com) allow scripts to be loaded from these two external URLs.
