
# DOM-Based Cross-Site Scripting (DOM XSS)

## Understanding DOM-Based Cross-Site Scripting (DOM XSS)

DOM-Based Cross-Site Scripting (DOM XSS) is a client-side vulnerability where malicious scripts are executed due to insecure manipulation of the **Document Object Model (DOM)** by JavaScript in the victim’s browser. Unlike traditional XSS, DOM XSS does not rely on unsafe server responses but occurs when client-side code processes untrusted data.

---

## What are Sinks in DOM XSS?

**Sinks** are specific JavaScript functions, properties, or methods that handle data in a way that may cause execution or rendering of attacker-controlled input, leading to DOM XSS vulnerabilities.
If untrusted data flows into these sinks without proper sanitization or validation, it can result in malicious script execution in the victim’s browser.

---

## Common DOM XSS Sinks

### 1. DOM Manipulation

* `document.write()`, `document.writeln()`
* `element.innerHTML`, `element.outerHTML`
* `element.insertAdjacentHTML()`
* `element.onevent` (e.g., `onclick`)

**Description:** Insert or write raw HTML, set attributes, or dynamically assign event handlers.

---

### 2. Location & Navigation

* `location`, `location.href`, `location.host`, `location.hostname`
* `location.pathname`, `location.search`, `location.protocol`
* `location.assign()`, `location.replace()`

**Description:** Control page navigation and inject code via URL manipulation.

---

### 3. Window & DOM APIs

* `open()`, `document.domain`

**Description:** Open new windows or manipulate domain for same-origin policy.

---

### 4. AJAX & XMLHttpRequest

* `XMLHttpRequest.open()`, `XMLHttpRequest.send()`
* `jQuery.ajax()`, `$.ajax()`

**Description:** Send or load data dynamically; unsafe handling may load malicious scripts.

---

### 5. JavaScript Code Execution

* `eval()`, `Function()`
* `setTimeout()`, `setInterval()`, `setImmediate()`
* `execScript()`, `execCommand()`
* `range.createContextualFragment()`

**Description:** Execute strings as code or create DOM fragments from HTML strings.

---

### 6. jQuery Sinks

* `add()`, `after()`, `append()`
* `attr()`, `html()`
* `insertAfter()`, `insertBefore()`

**Description:** DOM manipulation and attribute-setting functions that may inject code.

---

## Explanation

* These sinks act as execution points for malicious data.
* An attacker can control a **source** (like `window.location` or `document.referrer`) and pass data into these sinks.
* If the sink interprets data as code without sanitization or encoding, malicious scripts run inside the victim’s browser.

**Example:**

```javascript
document.write("<script>alert(document.cookie)</script>");
element.innerHTML = "<img src=x onerror=alert(document.cookie)>";
```

Both examples execute JavaScript from attacker-controlled input.

---

## Common Sources of Untrusted Data

* `window.location` (`href`, `search`, `hash`, `pathname`)
* `document.referrer`
* `document.URL`
* Cookies
* `window.name`

---

## How DOM XSS Works

1. When a page loads, the browser builds the DOM tree.
2. JavaScript manipulates the DOM to create interactivity.
3. If JavaScript takes **attacker-controlled data** from sources like URL parameters, fragments, or cookies and inserts it insecurely into the DOM, malicious scripts may execute.
4. This typically occurs when untrusted data flows into dangerous sinks.

---

## Prevention of DOM XSS

* Avoid dangerous sinks with untrusted data.
* Sanitize and encode inputs before inserting into the DOM.
* Use **safe alternatives** (`textContent`, `setAttribute`) instead of `innerHTML`.
* Avoid `eval()`, `Function()`, and similar execution functions.
* Use frameworks/libraries that auto-escape untrusted data.
* Implement **Content Security Policy (CSP)** headers to restrict inline JavaScript.
* Validate and sanitize URL parameters and fragments.
* Perform security testing focusing on client-side code paths.

## DOM-Based XSS Lab in PHP

```bash
dom-xss1.php
```
```html
<!DOCTYPE html>
<html>
<head>
    <title>DOM XSS Lab Example</title>
</head>
<body>
    <h2>Welcome to the DOM XSS Lab</h2>
    <p id="output"></p>

    <script>
        // Vulnerable: Extract 'name' parameter from URL
        // Example: http://localhost/web-pentest/dom-xss.php?name=Nikhil
        // BAD SINK: innerHTML
        const urlParams = new URLSearchParams(window.location.search);
        const name = urlParams.get('name') || '';
        document.getElementById('output').innerHTML = "Hello, " + name;
    </script>
</body>
</html>
```

### How to Use

1. Save as `dom-xss.php` in your web server directory.
2. Test in browser:

   * `http://localhost/web-pentest/dom-xss.php?name=Nikhil`
     → Output: **Hello, Nikhil!**
   * `http://localhost/web-pentest/dom-xss.php?name=<img src=x onerror=alert(1)>`
     → Executes an alert box (demonstrates XSS).

---

### Challenge

Fix the vulnerability by avoiding `innerHTML`.

**Safe Version:** 
> .textContent, .innerText

```javascript
document.getElementById('output').textContent = "Hello, " + name;
```

```bash
dom-xss2.php
```
```html
<!DOCTYPE html>
<html>
<head>
    <title>Advanced DOM XSS Lab</title>
</head>
<body>
    <h2>Advanced DOM-Based XSS Demonstration</h2>

    <p id="displayName"></p>
    <p id="displayEvent"></p>
    <p id="displayImage"></p>

    <script>
        // --- 1. From URL query parameters (?name=) ---
        const params = new URLSearchParams(window.location.search);
        const name = params.get('name') || '';

        // --- 2. From URL fragment/hash (#event=) ---
        const fragment = window.location.hash.substr(1); // removes '#'
        const fragParams = new URLSearchParams(fragment);
        const eventParam = fragParams.get('event') || '';

        // --- 3. From window.name (attacker-controllable) ---
        const imageTag = window.name || '';

        // --- Vulnerable sinks: dangerous DOM insertions ---
        // Vulnerable: innerHTML with untrusted parameter
        document.getElementById('displayName').innerHTML = "User: " + name;

        // Vulnerable: dynamically set event handler
        if (eventParam) {
            document.getElementById('displayEvent').innerHTML = '<button id="btnEvent">Click me</button>';
            document.getElementById('btnEvent').onclick = function() {
                alert(eventParam); // Executes attacker code
            };
        }

        // Vulnerable: injecting image tag from window.name
        document.getElementById('displayImage').innerHTML = imageTag;
    </script>
</body>
</html>

```

---

## Summary

* DOM XSS arises from **unsafe JavaScript manipulation** of untrusted data.
* Dangerous sinks (`innerHTML`, `eval()`, etc.) should be avoided.
* Use **sanitization, safe APIs, and CSP** to mitigate risks.
* Understanding sources and sinks is critical for securing modern web apps.
